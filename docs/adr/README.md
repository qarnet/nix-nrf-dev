# Architecture decision records

ADRs record accepted, lasting choices and the tradeoffs future changes must
consider. They are not implementation plans, progress logs or test reports.

Use numbered Markdown files with status, context, alternatives, decision and
consequences. Keep accepted rationale intact; a changed decision gets a new ADR
that supersedes the old one. Product scope, work history and acceptance evidence
belong in [the product backlog](../product/README.md). Current source ownership
belongs in [repository architecture](../development/architecture.md).
